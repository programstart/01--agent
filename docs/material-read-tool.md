## 1. 设计结论

素材读取工具采用以下方案：

- 示例项目使用 SQLite 关系型数据库作为数据源。
- 工具按素材 ID 进行精确查询，不做向量检索或模糊召回。
- 模型只能调用高层工具 `read_material`，不能直接连接数据库或生成 SQL。
- Agent 运行时负责参数校验和参数化查询。
- 每次调用只读取一个素材，避免一次返回大量记录。
- 素材库使用只读连接，本工具不创建、修改或删除素材。
- 不在本工具中执行审核规则判断、排期冲突判断或草稿保存。
- 默认不向模型返回完整正文，只返回审核所需元数据和有限长度的内容摘录。

## 2. 工具职责

### 负责

- 根据唯一素材 ID 读取素材记录。
- 将数据库记录转换为稳定的工具输出结构。
- 返回素材来源状态；如果数据源提供更新时间，则一并返回。
- 检查基础字段是否缺失。
- 对过长内容进行限制并明确标记截断。
- 将“不存在、参数错误、资料不完整、存储错误”作为结构化结果返回。

### 不负责

- 根据标题或正文模糊搜索素材。
- 自动创建不存在的素材。
- 修改素材状态或素材内容。
- 执行审核规则。
- 判断发布日期是否冲突。
- 保存排期草稿。
- 发布内容。

## 3. 数据源设计

示例项目采用一张只读素材表 `materials`。字段设计基线如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `asset_id` | TEXT，主键 | 素材唯一 ID，例如 `M01` |
| `title` | TEXT | 素材标题 |
| `platform` | TEXT | 目标平台 |
| `source_status` | TEXT | 素材库中的来源状态 |
| `content` | TEXT，可空 | 素材正文或说明，仅在服务端使用 |
| `metadata_json` | TEXT | 审核所需扩展元数据，存储为 JSON 字符串 |
| `version` | INTEGER，可选 | 素材版本；如果数据源提供，可用于排查数据变化，但不是题目要求的必填字段 |
| `updated_at` | TEXT，可选 | ISO 8601 格式的更新时间；不是题目要求的必填字段 |

`source_status` 的初始取值如下：

- `pending_review`：待审核，可以继续处理；
- `approved`：曾审核通过，但仍须重新检查当前规则和排期；
- `rejected`：曾审核拒绝，默认不自动排期；
- `archived`：已归档或停用，不进入排期。

来源状态不等于本次审核状态。读取工具只返回状态，后续动作由 Agent 根据当前任务判断。无法识别的状态按数据异常处理，不允许擅自放行。

基础完整性只检查 `asset_id`、`title`、`platform`、可识别的 `source_status` 和合法的 `metadata_json`。`content` 可以为空；`version` 和 `updated_at` 不是必填字段。某条审核规则是否依赖正文或其他扩展字段，由规则检查工具进一步验证。

查询必须使用允许字段列表，禁止使用 `SELECT *`。数据库连接、表名、SQL 和底层异常不得作为工具输出返回给模型。

## 4. 工具输入结构

### 基本信息

| 项目 | 约定 |
| --- | --- |
| 工具名 | `read_material` |
| 调用方 | Agent 模型 |
| 执行方 | Agent 运行时 |
| 副作用 | 无 |
| 幂等性 | 是；数据未变化时重复读取结果一致 |
| 单次读取数量 | 1 个素材 |

### 参数结构

```json
{
  "asset_id": "M01"
}
```

| 参数 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `asset_id` | string | 是 | 去除首尾空格后非空，最长 64 个字符；建议格式为 `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$` | 要读取的素材唯一 ID |

运行时将素材 ID 去除首尾空格后查询。示例数据按不区分大小写匹配，例如 `m01` 可匹配 `M01`，但输出始终保留数据库中的规范 ID。

如果用户一次要求读取多个素材，Agent 应逐项调用工具，每次只传入一个素材 ID。

## 5. 工具输出结构

所有成功、空结果和失败均使用同一顶层结构，便于模型和运行时稳定处理：

```json
{
  "status": "SUCCESS",
  "material": {
    "asset_id": "M01",
    "title": "示例素材",
    "platform": "short_video",
    "source_status": "pending_review",
    "metadata": {},
    "content_excerpt": "用于辅助审核的有限长度内容摘录。",
    "content_truncated": false,
    "updated_at": "<ISO-8601>"
  },
  "data_completeness": {
    "complete": true,
    "missing_fields": []
  },
  "error": null,
  "meta": {
    "query_mode": "primary_key",
    "contract_version": "0.2",
    "content_limit_chars": 1000
  }
}
```

### 顶层字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | string | `SUCCESS`、`INCOMPLETE`、`NOT_FOUND`、`INVALID_ARGUMENT` 或 `STORAGE_ERROR` |
| `material` | object 或 null | 找到素材时返回规范化素材数据；找不到时为 `null` |
| `data_completeness` | object 或 null | 素材字段完整性结果；没有可用素材时为 `null` |
| `error` | object 或 null | 非成功状态返回结构化错误；成功时为 `null` |
| `meta` | object | 查询方式、接口版本和内容截断上限 |

### `material` 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `asset_id` | string | 素材唯一 ID |
| `title` | string 或 null | 素材标题 |
| `platform` | string 或 null | 目标平台 |
| `source_status` | string 或 null | 素材库来源状态 |
| `metadata` | object 或 null | 已解析的审核元数据；解析失败时为 `null`，不得伪装为空对象 |
| `content_excerpt` | string 或 null | 最长 1000 个字符的内容摘录 |
| `content_truncated` | boolean | 原始内容是否超过摘录上限 |
| `updated_at` | string 或 null | 数据源提供时的最后更新时间；不是必填字段 |

完整正文只在服务端供规则检查工具使用，不进入模型上下文。规则检查工具负责说明它检查了哪些字段以及命中什么规则。

### `error` 字段

```json
{
  "code": "MATERIAL_NOT_FOUND",
  "message": "未找到指定素材",
  "retryable": false
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 稳定的机器可读错误码 |
| `message` | string | 面向 Agent 和用户的简短说明，不包含 SQL 或内部堆栈 |
| `retryable` | boolean | 是否允许运行时重试 |

基础错误码如下：

| 状态 | 错误码 | 处理 |
| --- | --- | --- |
| `INVALID_ARGUMENT` | `INVALID_ASSET_ID` | 请用户提供合法素材 ID，工具不重试 |
| `NOT_FOUND` | `MATERIAL_NOT_FOUND` | 请用户核对素材 ID，不创建草稿 |
| `INCOMPLETE` | `MATERIAL_FIELDS_MISSING` | 返回缺失字段，请求补充，不继续排期 |
| `INCOMPLETE` | `MALFORMED_METADATA` | 标记元数据损坏，请求修复，不猜测内容 |
| `INCOMPLETE` | `INVALID_SOURCE_STATUS` | 标记素材来源状态异常，不擅自放行 |
| `STORAGE_ERROR` | `MATERIAL_STORAGE_UNAVAILABLE` | 最多重试一次，仍失败则任务未完成 |

## 6. 状态处理

| 工具状态 | Agent 后续动作 |
| --- | --- |
| `SUCCESS` | 进入规则检查；仍需结合 `source_status` 判断是否允许继续 |
| `INCOMPLETE` | 列出缺失字段并请求补充；不查询时段，不保存草稿 |
| `NOT_FOUND` | 要求用户核对或补充素材 ID；不得虚构素材 |
| `INVALID_ARGUMENT` | 请求用户提供合法 ID；不得自动猜测 |
| `STORAGE_ERROR` | 在有剩余调用预算时最多重试一次；仍失败则返回工具失败 |

当 `source_status` 为 `rejected` 或 `archived` 时，读取本身仍可返回 `SUCCESS`，但 Agent 默认不继续安排发布。需要重新审核时，应由当前用户请求明确触发，并重新执行当前规则检查。

## 7. 调用与执行流程

1. 模型从当前用户请求中识别一个素材 ID。
2. 模型发出工具动作 `read_material`，参数只包含 `asset_id`。
3. 运行时校验参数，使用参数化查询按主键读取素材。
4. 运行时解析 `metadata_json`，生成受限长度内容摘录。
5. 运行时检查基础字段完整性，生成统一输出。
6. 模型观察结果，选择规则检查、请求补充、重试或结束。

示例：

- 用户请求：“审核素材 M01，要求在 18:00 发布。”
- 模型动作：`read_material({"asset_id": "M01"})`
- 成功观察：返回 M01 的元数据、来源状态和内容摘录。
- 后续动作：调用规则检查工具；此时尚未查询时段，也没有保存草稿。

## 8. 复检与既有排期

本题不要求素材必须带版本号。审核结果应按“当前运行读取到的素材快照”判断，不能把一次审核通过理解成永久有效。

### 同一次运行

如果素材审核通过、目标或替代时段检查完成，并且排期草稿保存成功，则当前任务已经完成，不需要再次执行同样的审核和排期。重复检查不会产生新的业务信息，并可能触发无意义的循环。

同一次运行内只有以下情况需要继续检查：

- 用户补充了素材信息；
- 用户改变了发布时间要求；
- 当前工具返回失败，需要进行一次有边界的重试；
- 素材、审核规则或排期数据在运行中发生变化；
- 需要用户确认替代时段。

### 新的运行或重复提交

1. 先根据原始用户请求计算业务幂等键。
2. 如果找到同一幂等键对应的有效草稿，返回已有草稿 ID，不再创建第二份草稿。
3. 数据源提供 `updated_at` 或 `version` 时，可以比较快照判断素材是否变化；没有这两个字段时，也可以仅比较本次读取的允许字段生成内部指纹。
4. 如果素材、适用规则或排期发生实质变化，旧审核结论和草稿可能已经过期，应重新检查后再决定是否返回、替换或标记旧草稿。
5. 用户要求确认草稿、改变时段或重新排期时，必须执行新一轮检查，不能直接沿用旧的审核通过状态。

### 已存在排期记录

本 Agent 只保存草稿，不能把草稿称为已发布。如果排期库中已经存在同一素材和同一请求对应的有效草稿：

- 重复提交时返回原草稿，不新增记录；
- 重新做冲突查询时必须排除该草稿自身，避免把它误判为其他素材占用；
- 如果已存在的是确认排期或已发布记录，应直接报告现有状态，不自动创建重复记录或修改原记录；
- 只有用户明确要求调整时，才作为新请求重新审核素材、规则和目标时段。

因此：

- **同一运行内审核通过并成功保存草稿：不需要再次检查，应结束。**
- **跨运行重复提交：先做幂等判断；数据未变时返回原草稿。**
- **确认、改期或数据发生变化后：必须重新检查。**
- **素材版本号：题目不要求，但可在数据源提供时作为检测数据变化的辅助信息。**

## 9. 重试与 Trace

- 读取工具本身不进行无界重试。
- `STORAGE_ERROR` 最多由运行时重试一次。
- `INVALID_ARGUMENT`、`NOT_FOUND` 和 `INCOMPLETE` 不自动重试。
- 同一运行中，素材快照未变化且已经成功读取时，可以由 Agent 状态直接复用观察结果，避免模型循环访问数据库。
- Trace 记录工具名、规范化后的 `asset_id`、结果状态、内容是否截断和错误码；数据源提供版本或更新时间时，可一并记录用于追踪。
- Trace 不记录完整素材正文、数据库连接串、SQL 明细或可能包含敏感信息的底层异常。

## 10. 安全与数据库访问

- 使用只读数据库账号或 SQLite 只读连接。
- 使用参数化查询，禁止字符串拼接用户输入。
- 设置查询超时，返回稳定错误码。
- 只读取允许字段，不暴露其他表或内部字段。
- 素材 ID 只作为参数，不可解释为 SQL 片段。
- 数据库不可用时返回工具失败，不能返回空素材并继续排期。

## 11. 后续工具测试基线

实现代码后，素材读取工具至少覆盖以下测试：

1. 正确 ID 返回完整素材和有限长度摘录。
2. 小写 ID 能匹配对应规范 ID。
3. 不存在的 ID 返回 `NOT_FOUND`。
4. 空 ID 或非法 ID 返回 `INVALID_ARGUMENT`。
5. 缺少基础字段时返回 `INCOMPLETE` 和明确缺失字段。
6. 元数据 JSON 损坏时返回数据异常，不默认为空。
7. 超长正文被截断，并设置 `content_truncated=true`。
8. 注入式 ID 不会改变 SQL 查询语义。
9. 数据库不可用时返回可重试的 `STORAGE_ERROR`。
10. 重复读取同一素材不会产生任何写入副作用。
