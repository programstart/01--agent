> 文档版本：0.3
>
> 当前阶段：第一阶段（可运行 MVP）
>
> 更新日期：2026-11-01
>
> 题目来源：[四道题目原图](../../../assets/all-four-questions-source.png)
>
> 状态：第一阶段、规则引擎 v2 与 30 分钟区间排期已实现，自动化验收通过

## 1. 背景与目标

内容团队在发布素材前，需要核对素材资料、审核规则和已有排期，并保存一份可确认、无冲突的发布草稿。

第一阶段只处理一个用户请求中的一个素材，但必须完成完整的动态决策闭环：

**读取素材 → 检查审核规则 → 查询发布时段 → 模型调整下一步 → 保存草稿、请求调整或结束**

系统只保存排期草稿，不连接真实发布平台，也不能把草稿标记为已发布。

## 2. 用户与成功标准

### 主要用户

需要为待发布素材做审核和排期确认的内容运营人员。

### 用户目标

- 确认指定素材是否满足当前审核要求；
- 判断期望发布时间是否可用；
- 在发生冲突或风险时得到明确原因和可执行的替代方案；
- 对可接受的方案保存一份排期草稿；
- 对不确定事项获得明确提示，而不是得到未经确认的结果。

### 成功标准

1. 用户能够通过可复制的 CLI 命令运行 Agent。
2. 系统根据工具返回结果动态调整下一步动作，而不是只执行固定分支。
3. 正常和冲突路径均产生可检查的执行记录。
4. 所有输出都区分审核结论、建议时段、待确认事项和草稿保存状态。
5. 相同素材请求重复执行时只保留一份对应草稿。
6. 工具失败、资料不足或达到执行上限时，系统返回明确的未完成状态。

## 3. 第一阶段范围

### 包含

- CLI 运行入口；
- 单个素材、单个发布时段要求的处理；
- SQLite 中的预置素材、审核规则和已有排期；
- 素材读取工具；
- 审核规则检查工具；
- 结构化规则与自然语言语义规则；
- 统一规则结果、证据和状态聚合；
- 时段查询工具；
- 排期草稿保存工具；
- 受限 ReAct 风格的工具调用循环；
- 草稿幂等保存；
- 当前排期快照的冲突检查；
- 结构化运行结果和公开 Trace；
- 离线 Mock 模型入口，用于无模型凭据时验证工具流程；
- 题目要求的基础验收测试。

### 第一阶段假设

- 用户请求中会提供素材 ID；不实现“无 ID 时自动发现全部待审素材”。
- 示例数据库预先包含素材、规则、确认排期和必要测试数据；不实现素材上传或素材编辑。
- 演示时区默认为 `Asia/Shanghai`，每次请求必须能够解析出带时区的发布开始时间。
- 第一阶段每次发布默认占用 30 分钟，使用半开区间表示；区间重叠才算冲突，首尾相接不冲突。
- 默认替代时段步频同样为 30 分钟，从原请求开始逐次向后查找。
- 精确发布时间视为硬性要求，未经用户确认不能替换。
- 第一阶段每次只新增或处理一个排期目标，已有排期中可以包含多个其他素材。

### 第一阶段不包含

- 多个新素材同时竞争同一时段时的全局分配或最优排期；
- 自动计算业务优先级；
- 自动删除、覆盖或迁移已有草稿；
- 复杂草稿过期检测和自动替换；
- 真实发布、撤回或审核审批平台接入；
- Web 界面或日历界面；
- 多 Agent；
- 向量检索和大规模素材内容 RAG；
- 生产级认证、消息队列、定时任务和线上部署；
- 完整素材版本控制；版本和更新时间仅作为可选诊断信息。

## 4. 输入

### 4.1 用户请求

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `asset_id` | 是 | 要审核和排期的素材 ID |
| `requested_at` | 是 | 期望发布时段的开始时间，统一到分钟精度 |
| `timezone` | 是 | 例如 `Asia/Shanghai` |
| `search_until` | 否 | 查询替代时段的最晚开始边界；默认只查询同一天 |

第一阶段请求可以使用结构化 CLI 参数。自然语言解析不是核心验收项，但 Agent 的说明和结果必须使用用户可理解的中文。

### 4.2 预置数据

| 数据 | 用途 |
| --- | --- |
| 素材数据 | 根据素材 ID 读取元数据、来源状态和审核所需内容 |
| 审核规则 | 判断素材是否通过、存在警告或被阻断 |
| 已有排期 | 查询确认排期、已发布记录和有效草稿的时段占用 |
| 已有草稿 | 支持重复提交识别，避免生成第二份草稿 |

素材、规则和确认排期由第一阶段提供并视为只读。只有草稿表允许写入。

## 5. 输出

每次运行至少返回以下信息：

| 输出 | 说明 |
| --- | --- |
| 素材 ID | 当前处理的素材 |
| 审核状态 | 通过、警告、信息不足或阻断 |
| 风险原因 | 命中的规则、缺失字段或其他阻止继续的原因 |
| 用户原始时间要求 | 不因模型建议而被覆盖 |
| 建议时段 | 原期望区间或明确标记的替代区间 |
| 待确认事项 | 例如替代时段、风险确认或资料补充 |
| 草稿状态 | 已保存、已有草稿、保存失败或未尝试 |
| 草稿 ID | 成功保存或复用草稿时返回 |
| 任务状态 | 完成、未完成或失败 |

## 6. 功能要求

### FR-01 请求校验

- 校验素材 ID、时间格式和时区。
- 信息不合法时说明具体字段，不调用后续排期工具。

### FR-02 素材读取

- 按素材 ID 精确查询，不把整个素材库发给模型。
- 素材不存在、资料不完整或数据库不可用时返回结构化结果。
- 不向模型返回完整长正文，只提供有限内容摘录；规则检查可在服务端读取完整数据。

### FR-03 审核规则

- 使用当前适用规则检查素材。
- 结构化规则使用确定性字段、集合、日期或格式条件。
- 自然语言规则使用语义审核器判断整体表达，不能只用关键词代替。
- 两类规则都返回统一结果，包括规则 ID、类型、严重等级、结论、原因和证据。
- 语义违规必须提供可在素材中逐字定位的原文证据。
- 程序必须校验规则 ID、严重等级和证据真实性。
- 阻断状态不得进入草稿保存。
- 警告状态可以生成建议，但必须标记待确认。
- 语义结果不确定时进入 `NEEDS_REVIEW`，不得视为通过。

### FR-04 时段查询

- 查询当前排期中的 30 分钟发布时段占用。
- 同一排期范围内，标准化后的半开区间发生重叠才构成冲突。
- 区间结束点与下一区间开始点重合不算冲突，例如 `18:00–18:30` 与 `18:30–19:00` 可以相邻。
- 已确认排期和已发布记录属于不可自动占用的时段。
- 同一幂等键对应的当前草稿在冲突检查中必须排除自身。
- 目标时段冲突时，从原请求开始每隔 30 分钟向后查找替代时段。
- 没有可行时段时返回未完成原因。

### FR-05 动态决策

- 模型必须根据素材读取、规则检查和时段查询的返回结果选择下一步动作。
- 至少支持正常路径和冲突路径两种不同决策结果。
- 模型不能绕过阻断规则直接保存草稿。
- 模型不能未经确认把精确发布时间视为已改期。
- 达到模型步骤或工具调用上限时停止，并返回已完成事项和未完成原因。

### FR-06 草稿保存

- 只保存草稿，不执行真实发布。
- 使用业务幂等键防止同一请求重复创建草稿。
- 使用用户原始时段且无审核风险时，不产生额外的待确认项，但草稿仍不等于正式确认或发布。
- 替代时段和非阻断风险必须带有待确认标记。
- 草稿保存状态、确认状态和发布状态必须分开记录。
- 保存失败时回滚写入，并明确返回失败。
- 不得出现“保存失败但回复成功”或“仅保存草稿但回复已发布”的情况。

### FR-07 新运行与重复提交

- 每次新运行都重新读取当前素材、规则和排期。
- 完全相同的请求先查询对应草稿；当前检查仍可继续时，返回原草稿 ID，不新增记录。
- 当前审核阻断或没有可保存时段时，本次运行返回未完成，旧草稿保持不变。
- 用户改期会生成新的请求身份并执行完整检查。
- 第一阶段不自动删除、覆盖、迁移或重新判定旧草稿；历史快照差异由现有风险原因和当前检查结果提示。

### FR-08 运行记录

- 记录步骤、工具名、参数、返回摘要、后续动作和简要决策依据。
- 不记录模型内部思维过程，不记录完整正文、密钥或数据库连接信息。
- 相同参数、相同结果且没有产生新信息的重复动作应终止，不允许无限循环。

### FR-09 执行边界

- 第一阶段最多执行 8 个模型步骤。
- 第一阶段最多执行 6 次业务工具调用。
- 素材读取的存储类错误最多重试 1 次。
- 达到上限必须返回明确的 `INCOMPLETE`，不能继续循环或声称完成。

## 7. 状态定义

状态分层记录，不能只用一个字段覆盖所有含义：

| 层 | 允许状态 |
| --- | --- |
| 素材读取 | `SUCCESS`、`INCOMPLETE`、`NOT_FOUND`、`INVALID_ARGUMENT`、`STORAGE_ERROR` |
| 审核结果 | `PASS`、`WARNING`、`NEEDS_INFO`、`NEEDS_REVIEW`、`BLOCKED`、`ERROR` |
| 时段结果 | `AVAILABLE`、`CONFLICT_WITH_ALTERNATIVE`、`NO_FEASIBLE_SLOT`、`INVALID_ARGUMENT`、`STORAGE_ERROR` |
| 草稿结果 | `NOT_ATTEMPTED`、`SAVED`、`EXISTING`、`REJECTED`、`INVALID_ARGUMENT`、`STORAGE_ERROR` |
| 运行结果 | `COMPLETED`、`INCOMPLETE`、`FAILED` |

## 8. 第一阶段验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 正常排期：素材完整、无规则风险、目标时段空闲 | 审核通过，保存草稿，返回新草稿 ID |
| AC-02 | 素材不存在 | 返回未找到，不创建草稿 |
| AC-03 | 素材必要字段缺失 | 列出缺失字段，不查询时段或保存草稿 |
| AC-04 | 素材命中非阻断风险 | 返回风险原因，草稿标记待确认 |
| AC-05 | 素材命中阻断规则 | 停止排期，不保存可发布草稿 |
| AC-06 | 30 分钟目标时段被其他素材占用、存在替代时段 | 保持原始要求，从 30 分钟后开始建议并标记待确认 |
| AC-07 | 目标时段冲突且无可行替代时段 | 返回未完成及具体冲突原因 |
| AC-08 | 相同请求重复提交 | 返回原草稿 ID，数据库草稿数不增加 |
| AC-09 | 草稿保存故障 | 返回保存失败，不出现成功或已发布描述 |
| AC-10 | 达到步骤或工具调用上限 | 返回 `INCOMPLETE`、已完成步骤和剩余问题 |
| AC-11 | 没有命中禁用词，但整体表达构成保本收益暗示 | 语义规则 `R006` 返回 `BLOCKED`，不保存草稿 |
| AC-12 | 明确说明市场波动和不承诺保本的正常表达 | 语义规则通过，最终可以保存草稿 |
| AC-13 | 语义审核结果不确定、遗漏、重复、越权规则或证据无效 | 返回 `NEEDS_REVIEW` 或 `ERROR`，不得视为通过 |

## 9. 交付质量要求

- 所有关键判断由确定性工具提供事实，模型负责在合法动作中选择下一步。
- 工具输出使用稳定结构，错误不依赖异常文本解析。
- 测试使用合成数据，不包含真实密钥或隐私数据。
- 正常路径和冲突路径分别保存实际输出和 Trace。
- 至少提交 3 组完整输入、输出和运行记录，并覆盖全部验收点。
- 模型可用时，使用真实模型能力完成一次端到端演示；模型不可用时允许使用离线 Mock 验证流程，但必须明确标注其边界。

## 10. 后续迭代候选

第一阶段完成后再评估：

- 多素材批量排期和全局冲突处理；
- 明确优先级与自动分配；
- 草稿过期检测、替换和版本管理；
- 更多时段搜索策略和用户交互式改期；
- Web/API 入口；
- 真实发布平台和审批流接入；
- 更完整的规则管理和大规模检索能力。
