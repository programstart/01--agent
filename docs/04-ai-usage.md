# AI 使用说明

> 更新日期：2026-11-01

## 1. 使用范围

本项目在设计和实现过程中使用了 Codex AI 辅助，主要包括：

- 分析 30 分钟时段重叠、冲突、确认状态和幂等语义；
- 设计四个工具输入输出；
- 根据用户选定的 LangGraph 路线，辅助细化状态图和条件路由；
- 编写 Python 实现、SQLite 表结构和合成数据；
- 编写 pytest 测试；
- 运行 Mock 示例和真实模型正常/冲突路径并生成 Trace；
- 实现结构化与自然语言语义规则并用程序校验模型返回的证据；
- 整理 README 和交付文档。

## 2. 用户决策

当前实现遵循用户在对话中明确确认的方向：

- 第一阶段只保存草稿，不接真实发布；
- 使用关系型数据库和合成演示数据；
- 第一阶段按默认 30 分钟的连续时段判断区间重叠；
- 使用 LangGraph 实现工作流；
- 使用轻量 CLI，不实现 Web 界面；
- 正常草稿无额外待确认项，替代时间或审核警告需要确认原因；
- 关键词未命中不能证明整体内容合规，需要增加自然语言语义审核。

## 3. 个人贡献

本项目的核心方案不是由 AI 自动决定的。候选人主导了以下产品、工作流和架构设计。

### 3.1 工作流设计

- 将第一阶段限定为单素材、单个发布时段要求的可运行闭环；
- 确定动态流程为“读取素材 → 审核规则 → 查询时段 → 模型决定下一步 → 保存草稿或结束”；
- 要求模型每轮根据工具观察决定下一步，而不是只执行固定业务流水线；
- 确定资料不足、审核阻断、时段冲突和工具失败时的停止与请求补充边界；
- 确定达到步骤或工具调用上限时必须返回 `INCOMPLETE`，不能继续循环；
- 确定正常、冲突和失败路径都需要可检查的输入、输出和 Trace；

### 3.2 技术栈选择

- 确定采用 LangGraph `StateGraph` 和自定义 `RunState`，而不是把业务逻辑隐藏在不可见的预置 Agent 中；
- 参与确定 Python、Pydantic、SQLite、CLI 和 pytest 的技术组合；
- 确定真实模型负责动作选择，审核、排期和保存事实由确定性工具产生；
- 要求提供离线 Mock 入口，同时保留真实模型正常运行路径；

### 3.3 工具与数据设计

- 素材读取工具按素材 ID 精确读取 SQLite，只读且不把完整素材库放入提示词；
- 结构化规则由程序逐条执行；自然语言语义规则交给隔离的语义审核调用，不把规则作者指令或 Agent 动作决策权交给素材正文；
- 明确 `PASS`、`WARNING`、`NEEDS_INFO`、`NEEDS_REVIEW`、`BLOCKED`、`ERROR` 的审核语义和处理边界；
- 决定将结构化规则与自然语言语义规则统一到同一规则引擎和结果结构；
- 要求语义违规必须带素材原文证据，语义不确定或证据无效时不得通过；
- 决定规则严重等级由规则库控制，模型不能自行提升、降低或创建规则；
- 确定每个发布请求默认占用 30 分钟，使用半开区间判断冲突，首尾相接允许；
- 确定时段工具从原请求开始每 30 分钟向后返回替代时段，替代时段必须标记待确认；
- 确定草稿保存是第一阶段唯一业务写操作，正式排期保持只读；
- 确定草稿使用幂等键、事务内二次冲突检查和数据库唯一约束；
- 区分原始请求时间、建议时间、保存状态、确认原因和发布状态；
- 确定正常草稿无需额外确认项；使用替代时间时仅在 `proposed_at` 与 `requested_at` 不同时加入 `ALTERNATIVE_TIME`；
- 确定审核警告产生 `RULE_WARNING`，审核阻断时不允许保存草稿；

### 3.4 验证与验收判断

- 提供真实对话模型凭据并要求进行真实模型验证；
- 要求正常和冲突两条路径均由真实模型产生实际输出和 Trace；
- 要求覆盖重复提交、保存失败、执行上限和无进展停止；
- 要求所有示例明确标注 Mock 与真实模型边界，不能把 Mock 结果冒充真实模型效果。

### 3.5 提交时可使用的贡献描述

> 本人负责该 Agent 的工作流、技术栈和工具契约设计。具体包括：确定单素材 LangGraph ReAct 闭环、动态工具决策和停止条件；选择并约束 LangGraph 状态图架构；定义素材读取、规则检查、时段查询和草稿保存四个工具的职责、输入输出、可信边界及状态语义；确定结构化规则与自然语言语义规则的统一审核模型，要求语义判断附带原文证据且不能替代程序硬约束；确定默认 30 分钟占用、30 分钟替代步频、半开区间冲突、替代时段待确认、幂等保存和审核阻断策略；设计正常、冲突、资料不足、重复提交、保存失败、预算耗尽和整体语义违规等验收场景，并使用真实模型完成正常、冲突、语义阻断与语义放行路径验证。

## 4. AI 辅助实现

AI 根据上述已确认的设计完成了主要代码起草、SQLite 表结构、合成数据、Pydantic 模型、pytest 用例、README 和交付文档初稿。

AI 生成内容的验证方式包括：

- 30 项 pytest 自动化测试；
- Python 编译检查；
- 依赖一致性检查；
- 五条 Mock 业务路径；
- 四条真实模型端到端路径；
- Markdown 链接和示例 JSON 校验；
- 检查 Trace 不包含模型密钥、服务地址或模型标识。

## 6. 安全边界

- 未提交真实密钥；
- `.env.example` 只包含变量名；
- Trace 不记录完整素材正文或数据库连接；
- 真实模型凭据仅在当前进程环境变量中使用，未写入项目；
- 真实模型未配置时不会发送数据到外部服务；
- Mock 示例不包含真实公司素材或隐私数据。
